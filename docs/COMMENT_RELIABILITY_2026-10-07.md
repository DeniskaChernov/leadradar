## Исправления сбора

- Знакомый ID комментария больше не останавливает ScrapeCreators: API не
  гарантирует сортировку страниц по времени. Лимиты страниц и кредитов сохранены.
- Если следующая страница падает, ранее оплаченные комментарии сохраняются;
  курсор указывает на страницу, которую нужно повторить. Ошибка видна в запуске
  и состоянии источника; baseline не отмечается успешно завершённым.
- FULL-публикации перепроверяются по установленному интервалу, даже если общее
  число комментариев прежнее. Это позволяет обнаружить замену старого
  комментария новым при неизменном счётчике.
- Фото и карусели из существующего public posts API не отбрасываются. Имя
  метода адаптера `get_reels` сохранено для совместимости.
- Повторное получение комментария восстанавливает отсутствующий Lead после
  сбоя между сохранением Comment и созданием Lead. Уже существующий Lead
  повторно не анализируется только из-за дубля ingestion.
- Сохранённый курсор не сбрасывается из-за незавершённого baseline. Наличие
  следующей страницы сохраняет PARTIAL, даже если исторических строк в базе
  больше текущего удаляемого счётчика Instagram.

Новые регрессии воспроизводят все перечисленные ситуации без внешней сети.
Документация провайдера:
[Public Posts API](https://docs.scrapecreators.com/v2/instagram/user/posts/),
[Comments API](https://docs.scrapecreators.com/v2/instagram/post/comments/).

## Запуски и интерфейс

- При отмене поиска запись RUNNING закрывается; повторное завершение не
  перезаписывает уже зафиксированный результат. Частичные ошибки не выглядят
  полностью успешным запуском. Исторический прерванный запуск не получает
  расходы последующих запусков.
- Ошибки сохранения начала запуска происходят до вызова провайдера и видны
  пользователю.
- Один процесс владеет файловой SQLite на всё время `app.main.run`. Блокировка
  получается до backup, миграций и восстановления RUNNING, работает между
  процессами и освобождается ОС после аварии. Второй прямой запуск не может
  закрыть чужой живой поиск. Для PostgreSQL распределённая блокировка не
  реализована; автоматическое закрытие RUNNING без эксклюзивного владения
  пропускается.
- Запросы интерфейса имеют таймауты; POST автоматически не повторяется.
  После неопределённого ответа на запуск интерфейс запрашивает текущий статус.
- Все кнопки поиска блокируются вместе. Ответ запуска не перетирает текущий
  прогресс; быстро завершившаяся проверка показывает итог.
- Разрыв связи и истёкшая сессия показываются в кабинете. Запрещённый
  sessionStorage и отсутствующий/сломанный IntersectionObserver не ломают
  страницу и не оставляют контент скрытым. Reduced motion учитывается.
- Обновлена версия ресурсов/PWA-кэша: `13.56.0-cloudflare-20261007`.

и публичным health, а анонимный доступ к feed должен возвращать 401.

## Границы покрытия

Discovery пока получает первую страницу публикаций каждого источника. Старые
публикации вне этой страницы не обновляются автоматически. Отдельное платное
раскрытие ответов на комментарии выключено (`include_replies=false`).
Ограничение 5 кредитов может отложить следующую страницу до другого ручного
запуска. PARTIAL в интерфейсе означает реальное неполное покрытие.

Quick Tunnel зависит от работающего Windows-компьютера и интернета. После
перезапуска туннеля адрес может измениться; это не круглосуточный облачный VPS.
Наличие новых HOT зависит от реальных публичных комментариев, а не гарантируется
каждой проверкой. Telegram-рассылка в режиме web-only не выполняется.
