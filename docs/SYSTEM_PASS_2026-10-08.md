## Исправленные сценарии

| Сценарий | Дефект | Реализованное поведение |
|---|---|---|
| Подозрительные / вне каталога | PostgreSQL-only `.astext` вызывал 500 на SQLite | Переносимый поиск JSON, включая кириллицу с Unicode escapes |

| CSV воронки | Молчаливое обрезание на 1000 строках | Потоковая выгрузка всех совпавших строк, прежние публичные поля и защита от CSV-формул |
| Воронка | `view=list` игнорировался шаблоном | Реальный режим списка и отдельный переключатель; фильтр сохраняет режим |
| Страница задач | С непустой SQLite сравнивались naive/aware даты | Сравнение UTC-моментов без 500; локальное отображение времени сохранено |
| Создание задачи | Параллельная проверка могла создать несколько задач | Транзакционная блокировка; точное повторение contact/lead/manager/time/note возвращает ту же задачу, включая закрытую |
| Следующий контакт | Последняя добавленная задача перезаписывала ближайшую; закрытие убирало остальные | Ближайшая открытая задача, затем ID; пересчёт в той же транзакции при создании/выполнении/отмене |
| Задачи ротанга | Ссылка «Написать» открывала мебельный HOT | Ссылка передаёт направление; закрытые/отсеянные лиды не предлагают новый контакт |
| Отменённые задачи | Нельзя было выбрать их в общем списке | Фильтр «Отменённые», корректная метка, без кнопки выполнения |
| Сумма продажи | USD и прочие валюты подписывались как «сум» | Валюта из неизменяемого `DealSaleSnapshot` в сделках, карточке лида и человека |
| Повреждённые запросы | Invalid JSON/нечисловой lead_id мог давать 500 | Понятный HTTP 400 в CRM, тарифах/курсе и Telegram-auth |
| Windows-остановка | Launcher успевал завершиться между проверкой и Stop-Process | Подтверждённое отсутствие процесса считается завершённой остановкой; ошибки доступа, замена PID и неудачный CIM lookup не скрываются |
| Мобильная главная | Декоративный элемент метрики создавал горизонтальный выход на 5 px | Декорация ограничена своей карточкой; проверены все страницы на мобильной ширине |

Сводки на страницах различают общее число результатов и число строк текущей
страницы. Доска показывает стадии для выбранной страницы, а не выдаёт её за
полную воронку. Пагинация не является поиском новых данных у провайдера.

Схема БД не меняется. История `contact_events` не переписывается. Создание задачи,
обновление следующего контакта и новое событие фиксируются одной транзакцией.
Для обычного создания новой задачи после отмены/выполнения нужно выбрать новое
время или текст; точная повторная отправка закрытую задачу не воссоздаёт.

## Проверки

Новые регрессии используют отдельные SQLite и блокируют внешнюю сеть:

- 331 запись в каждом из пяти списков; все ID доступны, пропусков/дублей нет;
  повторный порядок, крайние страницы и пустой поиск.
- Переходы с сохранёнными фильтрами, настоящее отображение списка, 1007 строк CSV.
- Кириллица JSON, одновременное сохранение четырёх одинаковых задач, повтор после
  закрытия, пересчёт ближайшего контакта при совпадении времени, другой менеджер.
- HOT ротанга, просмотр отменённых задач, USD во всех трёх представлениях.
- Повреждённый JSON и нечисловые идентификаторы возвращают 400.
- Chromium: 26 страниц при ширине 390 и 1440, непустые CRM/каталог, загрузка
  настоящего JS/CSS, отсутствие ошибок JavaScript и горизонтального выхода body.
  Все запросы перехватываются; единственный разрешённый POST создаёт пустую
  локальную сессию помощника в тестовой БД.
- Windows PowerShell 5/7: естественный выход, отказ доступа, замена PID,
  невозможность проверить процесс; никакие реальные процессы тесты не останавливают.

Итоговый `pytest`: **974 passed, 2 skipped за 700,97 с**. Пропуски относятся к
PostgreSQL без тестовой БД и Unix SIGTERM на Windows. Добавлено 49 случаев:
39 функциональных, 2 браузерных (52 посещения страниц) и 8 проверок Windows.
