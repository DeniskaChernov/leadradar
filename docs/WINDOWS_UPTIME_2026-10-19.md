# Восстановление сервера и устойчивость Windows-запуска — 19 октября 2026

## Подтверждённая причина

Скрипт `start_cloudflare_windows.ps1` останавливал сервер, который сам запустил,
при любой последующей ошибке туннеля, включая недоступность публичного адреса.
Локальный сервер при этом уже успешно отвечал на health-check. В
`.runtime/windows-logon.log` за 19 октября зарегистрированы четыре такие
попытки: 10:54:16, 10:55:46, 10:57:43 и 10:59:51 по Ташкенту. Соответствующие
журналы сервера показывают успешный запуск Uvicorn до ошибки внешней проверки.
В журналах cloudflared есть DNS timeout и `connection with edge closed`.

Service worker при сетевой ошибке навигации отдаёт сохранённый `offline.html`
с надписью «Нет сети». Эта надпись появляется и при остановленном localhost;
сама по себе она не определяет, отключился интернет или сервер приложения.

## Изменения

- Защищённый локальный кабинет запускается до скачивания cloudflared и любых
  обращений к Cloudflare. Ошибка DNS, загрузки бинарного файла, соединения с
  edge или публичной проверки не останавливает готовый локальный кабинет.
- Неуспешный холодный запуск, в том числе неподтверждённая защита входом,
  по-прежнему очищается. Проверки executable, command line и времени создания
  процесса сохранены; чужие процессы и повторно использованные PID не завершаются.
- Получение hostname больше не считается готовностью туннеля: сначала нужна
  запись `Registered tunnel connection`. До неё старый сервер остаётся работать.
- Для загрузки нового точного allowed hostname сервер перезапускается только
  при полном здоровом `/health` с отсутствующим поиском, очередью и AI in-flight.
  Занятый сервер сохраняется, конфигурация URL не меняется.
- Вместо принудительного HTTP/2 используется `auto`: Cloudflare выбирает QUIC
  с возможностью fallback на HTTP/2 при невозможности UDP-подключения.
  Основание: [официальные параметры cloudflared](https://developers.cloudflare.com/tunnel/reference/run-parameters/#protocol).
- Повторный запуск использует существующие сервер и туннель при совпадающей
  конфигурации. Режим ручного поиска, лимиты, токен и настройки бота не менялись.

## Данные и ограничения

До восстановления сделан backup `lead_radar-uptime-20261019-060525.db`.
В ходе работы пользователь самостоятельно запустил поиск: семь источников,
84 публикации, 11 новых комментариев/лидов. В старом server log зафиксированы
HTTP 500 ScrapeCreators при продолжении публикаций @aiko.uz и отдельный
APIConnectionError при AI-разборе. Они не выданы за успешный полный цикл.
Платный поиск, AI-вызовы для проверки и тестовые сообщения не запускались.

Все исходные 2483 `contact_events` совпали побайтово на уровне значений
строк; старые ID comments/leads/contacts сохранены. После пользовательского
поиска создан второй backup `lead_radar-uptime-postscan-20261019-085247.db`:
49 основных таблиц остались неизменны при окончательной сверке. Четыре
производных кеша пересчитывались штатным запуском приложения. В базе
555 comments/leads, 484 contacts, 2515 contact_events, 622 cost_events.
SQLite integrity = ok, foreign key errors = 0. Данные пользовательского запуска
не откатывались к старым backup.

Туннель не переносит приложение с Windows-ПК в облако. При выключении/сне ПК
либо остановке процесса кабинет будет недоступен. Временный hostname может
смениться при создании нового туннеля; постоянный домен не настраивался.
Исправление изолирует сбой Cloudflare от готового локального сервера,
но не обещает круглосуточную доступность работающего на пользовательском ПК сервера.
