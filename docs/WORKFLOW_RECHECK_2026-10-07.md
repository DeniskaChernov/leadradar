# Проверка комментариев и рабочих сценариев — 2026-10-07

Этап продолжает исправление ошибок после восстановления HOT. Изменения проверяются
на временных SQLite и шаблонах приложения, с запретом внешней сети в pytest.
Платный поиск, генерация через рабочие API и отметки отправки рабочим клиентам
для этого этапа не используются.

## Подтверждённые ошибки и исправления

- Сохранённый курсор истории подавлял проверку новых комментариев. При изменении
  подтверждённого счётчика или истечении срока проверки читаются первые страницы;
  курсор старой истории, провайдер и baseline сохраняются. Чтение исторических
  страниц больше не обновляет время проверки начала списка. Покрытие остаётся
  PARTIAL, пока сохранённая история не закончилась. Лимиты страниц и кредитов
  не увеличены; восстановление оплаченных страниц после ошибок сохранено.
- Положительный повторный анализ возвращал ручной NOT_LEAD в NEW. Сервис учитывает
  feedback и последнее неизменяемое событие решения менеджера, в том числе когда
  решение принято до первого AI-результата. Автоматический NOT_LEAD может быть
  пересмотрен; ручное решение отменяется явным возвратом в работу. Отрицательный
  повторный анализ теперь исключает неподтверждённый NEW из активной воронки,
  сохраняя стадии, в которых менеджер уже работает. Обработчик ошибки AI также
  блокирует короткую финальную запись до чтения: прежний код мог заменить
  параллельное ручное решение NOT_LEAD/TAKEN на AI_PENDING.
- Перетаскивание лида через несколько стадий выполняло несколько commit.
  Назначение, все промежуточные стадии и их события теперь сохраняются одной
  транзакцией. Короткая блокировка до чтения защищает от двух одновременных
  назначений, повторного создания сделки и повторных событий задачи.
- Отменённую задачу можно было выполнить; повторное возвращение NOT_LEAD давало
  ошибку и оставляло устаревший verdict. Отменённая задача возвращает конфликт;
  повтор возврата того же менеджера безопасен, feedback очищается. Проверка
  владельца выполняется и для операций, которые не меняют текущую стадию.
- Создание сделки допускалось для NOT_LEAD/WON/LOST. Сервис запрещает создание
  и редактирование на закрытом лиде; карточка показывает существующую сделку
  для просмотра. Закрытие уже существующей открытой сделки также не обходит
  ручной NOT_LEAD. Одновременные запросы создания возвращают одну сделку;
  повторные запросы продажи сохраняют один snapshot и одно событие.
- Смена score после commit могла скрыть сохранённый HOT-результат и вернуть
  ложную ошибку. Внутреннее чтение результата допускает сохранённую историю,
  отключая дальнейшие действия для низкого score. Повтор отметки отправки
  сохраняет исходный текст, время и события; актуальная HOT-очередь не расширена.
- Медленный ответ explain предыдущего клиента перезаписывал следующую карточку.
  Ответ привязан к текущему открытию; закрытие отменяет запрос, повторное открытие
  сбрасывает таймер закрытия и сразу устанавливает правильную ссылку.
- Формы повторно включали кнопку до перезагрузки: две заметки создавались двумя
  нажатиями. Форма блокируется до подтверждения и до перезагрузки после успеха;
  поля не позволяют дописать текст, который исчез бы при reload. При ошибке
  или отмене восстанавливается исходное состояние полей. HTML вместо API JSON,
  null, массив и ok:false больше не считаются успешным сохранением.
- Ссылки «Написать» из карточек ротанга теряли vertical и открывали мебельного
  клиента. Ссылка содержит vertical выбранного лида; это проверено реальным
  рендерингом карточки и выбором того же клиента на HOT.

## Остающиеся ограничения

Провайдер не гарантирует порядок комментариев. Проверка первых настроенных
страниц не даёт гарантии немедленного обнаружения записей глубоко в выдаче;
отдельный второй постоянный курсор для пагинации нового начала списка не добавлен.
Блокировка формы защищает от повторного нажатия в текущей странице; отдельный
серверный ключ идемпотентности для добавления заметки не введён. Несохранённая
другая форма всё ещё может потерять правки при перезагрузке после соседнего действия.
Поиск запускается вручную, обычный лимит — 5 кредитов. Replies и приватные данные
не собираются; первая страница discovery и Windows-хост остаются прежними
ограничениями. Временный Cloudflare-адрес может измениться при перезапуске туннеля.
