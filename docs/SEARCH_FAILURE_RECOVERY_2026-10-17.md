# Восстановление запуска поиска — 17 октября 2026

## Причина блокировки и подтверждённая сверка

Поиск #72 от 16 октября завершился с ошибкой: ScrapeCreators ответил HTTP 500
при продолжении списка публикаций @aiko.uz. Исходное тело с доказательством
списания не было сохранено. Резерв №451 стал UNCERTAIN; защита расходов
блокировала следующие запросы Instagram. Это не ошибка авторизации кабинета
и не исчезновение сохранённых лидов.

Выполнен один запрос истории провайдера с фильтрами endpoint/statusCode.
Официальная стоимость [get-api-usage](https://docs.scrapecreators.com/v1/account/get-api-usage/)
— 1 credit. Диагностика имеет собственный резерв №476, FINALIZED, и одну
запись расхода `scrapecreators_account/get_api_usage`. Новый поиск не запускался.

История однозначно сопоставлена по пути, @aiko.uz, cursor, времени и статусу:

- request ID `1823511d-e5b7-4310-b0e6-ddc766dc2c9f`;
- request_time `2026-10-16T10:50:53.89+00:00`;
- status_code 500, success=false, **credits=0**.

Штатная сверка закрыла №451 как RELEASED / actual_units=0. Доказательство
добавлено к резерву; ложная запись списания не создавалась. Бесплатный preview
после сверки: `can_start=true`, blocking_reasons пусты.

Нельзя считать каждый HTTP 500 бесплатным: в той же истории есть более старый
HTTP 500 с credits=1. Поэтому правило остановки без доказательств сохранено.

## Предотвращение повторных ошибок

1. HTTP-адаптер сохраняет явные credit-факты из JSON до проверки HTTP-статуса.
   ScrapeCreators теперь не теряет `credits_charged=0/1` в ответах с ошибкой.
   При отсутствии доказательства резерв по-прежнему остаётся UNCERTAIN.
   Внутри адаптера один доставленный запрос соответствует одной попытке.

2. При ручном переразборе 17 октября OpenAI вернул HTTP 200, но структурированный
   результат был обрезан: `EOF while parsing an object`. SDK проверял JSON до
   передачи usage приложению. Это создало UNCERTAIN №457, а ValidationError
   ошибочно стал PERMANENT_FAILURE для AIRequest #243 / лида #334.

3. Обработчик OpenAI сначала читает raw envelope и usage, затем проверяет JSON.
   Incomplete, отсутствующий результат и неверный формат становятся AIOutputError.
   Полученный HTTP-ответ учитывается один раз даже при невалидном результате;
   известные токены сохраняются в запросе и cost_events. Резерв закрывается
   с success=false, сигнал остаётся для явного повторного разбора. Ошибки без
   доказанного ответа по-прежнему не превращаются в выдуманное списание.

4. Отключены внутренние повторы SDK (`max_retries=0`), timeout 60 с меньше lease
   180 с. Это устраняет скрытые попытки внутри одного резерва. Лимит результата
   увеличен с 2000 до 3000 tokens; инструкции ограничивают длину объяснений
   и запрещают повторение пробелов. Prompt contract `lead-v3.2-bounded-output`
   имеет новый fingerprint; сохранённые старые оценки не переписываются.

5. AIRequest #243 переведён из ошибочного PERMANENT_FAILURE в RETRYABLE.
   Сохранены исходная ошибка, контекст, число попыток и все оценки. Автоматический
   повтор не запускался. Резерв #457 остаётся UNCERTAIN: старый SDK потерял usage,
   и подтверждённых токенов для восстановления нет. Эта сверка относится к
   OpenAI и не блокирует поиск Instagram. 17 AI_PENDING сохраняются до ручного
   разбора и в рамках дневного бюджета.
