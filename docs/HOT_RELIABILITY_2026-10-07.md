# HOT: загрузка и работа с клиентами — 2026-10-07

Проверка проведена по жалобе «страница зависает или не загружается».
Работа относится к checkout `leadradar-main-audit` репозитория
`DeniskaChernov/leadradar`; платный поиск и отправка сообщений не выполнялись.

## Подтверждённые причины

- Незавершённая загрузка Telegram SDK в `<head>` останавливала разбор HTML:
  тело документа и HOT отсутствовали. Незавершённая загрузка Lucide
  задерживала следующий deferred `app.js`: страница была видна, кнопки не работали.
  Это воспроизведено в Chromium с настоящими шаблонами и зависшими внешними запросами.
- При 40 карточках CSS ограничивал высоту workspace, но содержимое очереди
  определяло высоту grid. На ширине 800 px карточка уходила до y=5034 при
  высоте родителя 600 px и `overflow:hidden`. На 390 px длинный комментарий
  расширял страницу до 1987 px. Сам HTTP `/hot` в момент аудита отвечал
  примерно за 0,3 секунды и не вызывал provider API.
- Ввод текста снимал блокировку «Отправил» во время POST. Подготовка оставляла
  редактор доступным и поздним ответом затирала новую правку. API сохранения
  ручного текста не имел кнопки в интерфейсе.
- Повторный `sent` с тем же текстом возвращал конфликт; генерация после
  отправки сбрасывала `sent_at`; закрытый лид принимал новый ручной черновик.
  Параллельная генерация могла затереть сохранённую правку.
- Стадии CRM коммитились раньше отметки отправки. Сбой финального сохранения
  мог оставить `OFFER_SENT` без записи об отправленном тексте.
- Повторный анализ целиком заменял `analysis_details` и стирал HOT-черновик,
  включая отметку отправки. Это воспроизведено без внешних API.
- Прямая ссылка на лид с другой страницы не открывала эту страницу очереди;
  устаревшая ссылка могла открыть закрытого или несвежего клиента вне очереди.

## Реализовано

Внешние Telegram/Lucide скрипты асинхронны и не задерживают основной интерфейс.
Поздняя загрузка иконок и Telegram инициализируется отдельно; обычный браузер
не получает Telegram-оформление без `initData`. Шрифт необязателен, его загрузка
не блокирует отрисовку. В CSP разрешены соответствующие CSS/font домены.
Регистрация service worker перенесена из запрещённого CSP inline-кода в локальный
`app.js`; её ошибка не прерывает HOT. Повтор из офлайн-оболочки использует обычную
ссылку, без запрещённого inline-обработчика. Версии HTML/JS/CSS/PWA согласованы:
`13.56.0-cloudflare-20261007-hot`.

Очередь имеет собственную ограниченную прокрутку; карточка и страница растут
по содержимому. Длинные строки переносятся. Выбранный клиент выделен,
виден в прокручиваемой очереди; проверены ширины 390, 800, 1024 и 1440 px,
40 карточек, длинный комментарий и пустая очередь.

Кнопка «Сохранить текст» сохраняет ручные правки без генерации. Несохранённый
текст помечен и защищён подтверждением при переходе. Подготовка, сохранение
и отметка отправки используют общую блокировку интерфейса, включая подтверждение.
Ошибочный ответ, таймаут и ошибка сохранения не очищают редактор и не повторяют POST.
Ответ API не может включить изначально выключенную генерацию.

Все записи HOT сериализованы через DB claim; отправленные и закрытые предложения
защищены. Повтор сохранения неизменного текста и повтор `sent` с тем же текстом
не добавляют события. Сохранённый черновик доступен при выключенном GPT без
нового платного вызова. Новый/force запрос сохраняет запрет генерации.
Переходы CONTACTED/OFFER_SENT, `sent_at` и события фиксируются одной транзакцией
через общий CRM helper, с прежними правилами переходов.

Повторный анализ сохраняет HOT-метаданные из актуальной строки БД. Анализ и
финальные записи HOT блокируют строку перед чтением/слиянием JSON в короткой
транзакции. Генератор и анализатор работают вне этой блокировки; медленный ответ
не удаляет текст или отметку, сохранённые менеджером во время анализа.

Позиция выбранного лида определяется SQL по тем же фильтрам и порядку всей очереди.
При устаревшем/закрытом/несвежем/чужом направлении открывается доступный клиент
с пояснением; пустая очередь отображается явно. Исторические карточки сохранены.

## Практические границы

отправляет его в Instagram и только затем нажимает «Отправил».
Сбои подключения и отказ GPT отображаются как ошибки действия; их отсутствие
в будущем не гарантируется. Поиск остаётся ручным, обычный лимит — 5 кредитов.
Прежние ограничения сбора комментариев и Windows-хостинга этим этапом не менялись.
