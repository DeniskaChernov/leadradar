Схема БД не меняется. Ключ новой заметки/ответа помещается в payload нового
`contact_events`; существующая история не редактируется. Ключ ограничен 128
символами (буквы/цифры и `._:-`, первый символ — буква/цифра) и действует
в области клиента, менеджера и типа события.
Повтор с другим содержимым возвращает 409. Повтор уже сохранённого ответа
возвращает квитанцию даже после переназначения лида; новое действие прежнего
менеджера отклоняется проверкой владельца.

Клиентский ключ меняется при редактировании формы и очищается после подтверждения.
Намеренное повторное добавление одинакового текста получает новый ключ. Если
sessionStorage недоступен, повтор защищён в памяти до перезагрузки. Старые
вызывающие стороны без ключа получают детерминированную дедупликацию точного
содержимого; для нового идентичного события следует передавать новый ключ.

Пагинация секций сохраняет направление и страницы других секций; переход
возвращает к нужной истории через якорь. Счётчики комментариев и источников
считаются по всей базе клиента. Сжатие однотипных CRM-событий обозначено как
сжатие на текущей странице. HTML заметок экранируется обычным шаблоном Jinja.

Суммы CRM ограничены существующим Numeric(14,2), количество — PostgreSQL Integer.
Идентификаторы из JSON не обрезаются до целого и не выходят за signed 64-bit.
Цена/валюта неизменяемого снимка продажи остаются прежними.

Повторяющиеся курсоры обнаруживаются в адаптере и бюджетной оболочке, включая
цикл из нескольких курсоров. Уже выполненные страницы оплачены и учитываются
даже при неполной выборке. Автоматический повтор или fallback для обхода бюджета
не добавляются. Добор продолжается только при следующем ручном запуске.
