## Подтверждённые дефекты и исправления

1. Повреждённый ответ провайдера мог отбрасывать валидные комментарии той же
   страницы или предыдущей страницы прямого адаптера. Теперь валидные публичные
   записи сохраняются; повреждённая страница остаётся PARTIAL с курсором для
   следующего ручного повтора. Дата успешной проверки и подтверждённый remote
   count не обновляются при ошибке. Немедленного оплаченного повтора нет.
   Privacy/budget blocks продолжают останавливать обработку и fallback.
2. Запоздалый GET старого состояния мог показать предыдущий итог и разблокировать
   кнопку после принятого POST нового поиска. Запросы статуса и preview получают
   поколение; старые ответы не применяются. Результат POST дополнительно
   проверяется свежим статусом без повторной отправки POST. Старый idle во время
   ещё незавершённого POST также не применяется; блокировка сохраняется до
   актуального статуса после завершения запроса.
3. Controller сохранял last_stats предыдущего поиска во время нового запуска
   и при ранней ошибке. Принятый запуск теперь немедленно очищает старые
   счётчики, ошибку и дату завершения. Отклонённый повтор не меняет состояние
   действующего запуска.
4. SQLite `mode=memory` без реально включённого URI мог отключить блокировку
   файловой базы: SQLAlchemy игнорирует этот параметр в такой конфигурации.
   Путь и режим теперь определяются по фактическим connect arguments SQLAlchemy.
   Проверены дисковая база, URI aliases и варианты boolean URI.
5. CostEvent, уже сохранённый в момент завершения поиска, мог исключаться при
   одинаковой временной метке. Верхняя граница завершения включена, а начало
   следующего запуска остаётся строгой границей. Одинаковое started_at
   различается по ID, чтобы не присвоить расход двум запускам.

В прогрессе используется «публикации», поскольку адаптер уже сохраняет фото,
карусели и Reels. Имена API-полей оставлены совместимыми. Версия ресурсов
и PWA-кэша обновляется согласованно до `13.56.0-cloudflare-20261007-r2`.

Все ошибки воспроизведены на временных базах или в Chromium с mocked HTTP.
Код бизнес-логики остаётся в services/providers; handlers не обращаются к
провайдерам. Схема БД этим этапом не меняется.

## Ограничения

Discovery всё ещё читает первую страницу публикаций. Отдельное раскрытие ответов
на комментарии выключено. При сохранённом backfill cursor новые комментарии
в начале списка могут задерживаться до окончания предыдущей пагинации;
отдельное планирование head/backfill требует следующего изменения. Ограничения
страниц и бюджета остаются явными. Полное покрытие Instagram не заявляется.

Сервер зависит от работающего Windows-компьютера и интернета. В этом этапе
проверяется обновление сервера с сохранением текущего Quick Tunnel;
перезагрузка ОС и новые реальные запросы Instagram/OpenAI не планируются.
