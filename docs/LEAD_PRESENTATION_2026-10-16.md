# Точные оценки и действия по всей системе — 16 октября 2026

## Действия согласованы с очередью HOT

Карточка лида, обе версии радара (группы и подробная таблица), список клиентов,
канбан и задачи раньше независимо проверяли балл и разные наборы статусов.
Это могло давать «Написать» для устаревшего сигнала, неподходящего ассортимента,
отправленного предложения или переговоров. Теперь все эти поверхности получают
принадлежность отображаемых лидов реальной очереди через
`HotOutreachService.queued_lead_ids`. Запрос использует исходный фильтр HOT,
выполняется один раз для страницы и не обращается к провайдеру.

На главной сильные сохранённые сигналы остаются видны: допустимое действие
открывает HOT с правильной вертикалью, остальные ведут в обычную карточку.
Карточка человека продолжает использовать ранее исправленный `contact_target`.
В радаре «Взять в работу» показывается для незакреплённых лидов на допустимых
начальных стадиях. Проверка и SQL-захват используют общий набор статусов;
правила назначения и история действий сохранены.

## Уверенность и роль покупателя

Раньше API объяснения превращал дробное `0.85` в `0`, карточка могла показывать
`0.85%`, радар — `85%`. Целое `1` в радаре превращалось в `100%`. При отсутствии
уверенности в карточке также подставлялось вымышленное значение 50%.

Общий преобразователь различает целые проценты (включая 0 и 1) и старые дробные
значения: `0.85` / `"0.85"` → 85%; дробное `1.0` / `"1.0"` → 100%; целое `1`
и строка `"1"` → 1%. Некорректные значения, boolean, NaN/Infinity и числа вне
0–100 считаются неизвестными. Отсутствие значения не подменяет сохранённый ноль.
При отсутствии основного поля используются сохранённый confidence_score или
соответствующий фактор; некорректное основное поле не маскируется запасным.

Карточки и API используют этот преобразователь. В окне «Почему это лид?»
показаны сохранённая уверенность и роль покупателя. В радаре роль также
подписана по-русски, например «Розничный покупатель». Исходные факторы оценки,
ограничения ассортимента и итоговая уверенность остаются отдельными данными;
при уточнении ассортимента итоговая уверенность может быть ниже исходного фактора.
Исходные оценки и тексты в БД не переписываются, GPT для отображения не нужен.
