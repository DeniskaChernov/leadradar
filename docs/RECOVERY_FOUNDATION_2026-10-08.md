# Lead Radar — восстановление и диагностика

Дата: 2026-10-08. Репозиторий DeniskaChernov/leadradar, исходный код `39425c0`.
Этап продолжает дорожную карту R0/R1. Рабочая среда: Windows, SQLite,
web-only и существующий временный Cloudflare tunnel.

## Найденные дефекты и изменения

До исправления регрессии воспроизвели потерю зафиксированных WAL-данных при
обычном копировании файла, восстановление поверх занятой базы и невалидный
JSON-журнал при кавычках/переносах. Исходный целевой прогон: 5 failed, 1 passed.

- `database_backup_service`: SQLite Backup API вместо обычной копии, integrity/FK,
  standalone snapshot, deadline, fsync и публикация только проверенного файла.
- Startup/manual backup: фактический путь DATABASE_URL, ручной обход только
  startup-флага, retention после успешной публикации, сохранение чужих копий.
- Restore: общий runtime lock, отказ при WAL/SHM/journal, проверка таблиц и точной
  известной ревизии, сохранение исходного файла и замена после подготовки снимка.
  `--force` обходит только подтверждение, не защиту работающей базы.
- JSON application logs: корректное экранирование текста и исключений.
- Журнал процесса: запуск, build, run_id/PID, фаза, heartbeat раз в 30 секунд,
  завершение и тип ошибки; без текста исключения и реквизитов подключений.
- Страница «Система»: время запуска/последнего подтверждения работы, состояние
  прошлого запуска и явное отделение процесса от доступности внешних API.

Улучшение не меняет Instagram-адаптер, правила классификации, контактную историю,
оплату или доставку сообщений. Предпочтение пользователя — ручной поиск,
обычный предел 5 кредитов — сохранено.

## Что остаётся открытым

- RUNNING в предыдущем receipt означает отсутствие записи завершения.
  Это не объясняет причину остановки. Windows force stop, пропадание питания
  и аварийное завершение здесь не различаются. Старый процесс до этого этапа
  не оставлял receipt. Полная диагностика launcher/tunnel ещё не внедрена.
- Receipt SQLite хранится рядом с базой; PostgreSQL/memory — только в памяти.
  Отказ записи диагностируется, но не останавливает кабинет.
- `/ready` проверяет процесс/БД/схему, не делает live-запрос Instagram/OpenAI.
  Heartbeat также не доказывает работоспособность источников.
- JSON-формат относится к application logging. Uvicorn/Alembic могут использовать
  собственный формат. Универсальная очистка текста старых журналов не внедрена.
- Restore lock координирует Lead Radar; сторонние SQLite-подключения нужно закрыть.
  Очень ранние схемы без современных обязательных таблиц не поддерживаются
  этим restore. Файл `.original` может быть повреждённым и не является backup.
- Внешняя копия, реальный reboot, 72 часа наблюдения, проверенный PostgreSQL
  cutover и автономный сервер остаются отдельными задачами.
