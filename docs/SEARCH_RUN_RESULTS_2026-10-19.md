# Отдельные результаты поисков — 19 октября 2026

## Поведение

У каждого запуска теперь есть страница `/searches/{id}` и запись в истории
`/searches`. На странице поиска и в окне завершения доступны прямые переходы:
«Новые лиды», «По компаниям», «По постам», «Все новые комментарии».
Частично завершившиеся и пустые поиски доступны наравне с успешными.
Ссылка открывает выбранный запуск; переход к компании, публикации, следующей
странице или смене фильтра не подмешивает общую базу радара.

В списке лидов человек показан один раз: выбирается оценённый кандидат,
затем более высокий балл и детерминированный порядок по дате/ID. Выбор делается
после фильтров и до пагинации. В разрезе постов человек показан один раз
в каждом посте, где оставил новый сигнал. «Все новые комментарии поста»
открывает исходные комментарии данного запуска и поста, очищая фильтры
по тексту и силе лида. Все подтверждения доступны в истории клиента.

Новый результат означает новую сохранённую запись/кандидата, а не обязательно
человека, который никогда прежде не встречался. Новый комментарий знакомого
контакта сохраняется как новый интерес. Повторная загрузка уже сохранённого
комментария не создаёт результата в следующем поиске. Разные люди с одинаковым
именем не склеиваются. Исходные комментарии, лиды и `contact_events` не удаляются.

Счётчики разделяют новые комментарии, уникальных людей, HOT по текущей оценке
и ожидание анализа. Первичные статистические `leads_created` подписаны
«кандидаты до оценки»: это не обещание такого же числа квалифицированных лидов.
В итогах выбранного запуска значения приведены до фильтров; внутри компании
и поста показываются значения текущей выборки. HOT-фильтр не принимает
неоценённых/отсеянных кандидатов за подтверждённых горячих лидов.

Кнопки режимов расположены над статистикой и видны на узком экране.
Объяснение правил свёрнуто в native details. Навигация работает обычными
ссылками без зависимости от JavaScript. История: 20 запусков на страницу;
уникальные люди: 50; посты: 8 с превью до 12 карточек; отдельный пост:
по 50 комментариев. Массового скрытого ограничения всей выборки нет.

## Хранение и совместимость

Миграция `ca219b748d30` добавляет nullable `result_tracking_version` и `vertical`
в `monitor_runs` и таблицу `search_result_origins`. Первичный ключ — comment_id;
два внешних ключа связывают создание комментария и создание лида с их запусками.
Связь комментария коммитится вместе с исходным сигналом. Связь лида — вместе
с лидом и событием контакта, до уведомлений и AI-анализа. Повторная обработка
не переносит происхождение в другой запуск. Восстановление отсутствующего
лида в следующем запуске сохраняет исходный запуск обнаружения комментария.

Номер запуска передаётся из контроллера в обычный поиск и проверку веток,
а также из CLI `--once`. Polling API возвращает `last_run_id`, чтобы даже
быстро завершившийся поиск открывал собственные результаты. После перезапуска
процесса история и связь с запусками сохраняются в БД.

Старые поиски не имели точной связи с результатом. Для них используется
интервал создания записей, ограниченный завершением и началом следующего
поиска. На экране есть явная пометка о восстановлении по времени.
Такой интервал не объявляется точной реконструкцией. Для нового запуска
версии 1 отсутствие результатов означает пустой результат, без отката
к выборке по времени или ко всей базе.

Исправлено сравнение кириллицы при фильтрации сигналов в SQLite:
`leadradar_casefold` регистрируется один раз для соединения, включая уже
открытые pooled connections. Текст и строка запроса приводятся одной функцией;
исходные строки БД не меняются. Для остальных СУБД сохраняется SQL lower.
